Issues Identified

A. It degenerates into a teaching essay

Root Causes Across All Runs

1. Dataset gravity wells

The model falls into: Codeforces mode, math-solver mode, explanation mode. This means PromptCoT-style behavior wasn't dominant enough in training.

2. Lack of strong anchoring

Your foundational-concepts → problem pipeline is not rigidly enforced. The model slips into whatever pattern it finds easiest.

3. Missing negative examples

It is never punished for: turning problems into solutions, drifting to coding tasks, ignoring concepts.

4. Not enough true PromptCoT exemplars

PromptCoT problems require a very specific pattern of reasoning — you likely need more curated samples.

Lessons Learned & Recommendations

  • Documentation Quality: The original paper lacks sufficient implementation details for reproduction
  • Resource Requirements: GPU infrastructure costs exceeded initial estimates
  • Data Preparation: Annotation and data synthesis processes are more complex than described
  • Hyperparameter Tuning: Critical parameters not adequately specified in methodology

Recommendations for Future Reproduction Attempts

  1. Contact original authors for implementation details and missing code
  2. Start with smaller-scale experiments before full reproduction
  3. Implement comprehensive logging and monitoring from the beginning
  4. Consider open-source alternatives for infrastructure to reduce costs

Conclusion

The attempt to reproduce PromptCoT from arXiv:2509.19894v1 revealed significant gaps between the theoretical description and practical implementation. While the conceptual framework shows promise, the lack of reproducible details makes independent verification challenging. The total cost of $136.007 across GPU infrastructure and annotation services highlights the resource intensity of modern ML research reproduction.
